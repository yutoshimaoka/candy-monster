## LP実装 進行管理スキル（起動ワードでSTEP順に自動進行）

> このスキルは **進行状況の表示と、次STEPの自動起動**を担当します。選択肢は出さず、STEP順に進めます。
> 実際の作業は各STEPのスキル（project-setup / figma-mcp-connect / figma-read / lp-implementation / lighthouse-check / deploy-preview / github-review）が行います。

### 🔑 起動ワード（これを言えば必ず発動）

以下のいずれかを送ると、このスキルが進行状況を表示します。**確実に発動させたいときは固有ワードの `lp-start` を使ってください。**

| 目的 | 起動ワード（推奨） | 補助ワード（これでも発動） |
|------|-------------------|--------------------------|
| 開始・現在地表示 | `lp-start` | START / スタート / 始める |
| 進捗確認 | `lp-status` | 進捗 / 今どこ / 残タスク / ステータス |
| 次へ進む | `lp-next` | 次は何 / 次へ |

> 💡 `START` など一般的な語は他の文脈で拾われないことがあります。**確実に動かすなら `lp-start` / `lp-status` / `lp-next` の固有ワードを使う**のが推奨です。

### このスキルを使うタイミング
- 上記の起動ワードが送られたとき（最優先で発動する）
- 各STEPが1つ完了したとき（自動で残タスクを表示する）

---

### 進行状況の管理方法

進捗はプロジェクトルートの `PROGRESS.md` で管理する。無ければこのスキルが作成する。
各STEPの状態は `[ ]`（未完了）/ `[x]`（完了）で表す。

---

### 起動ワードが送られたときの動作（lp-start / lp-next）

**選択肢は出さない。STEP順に、次にやるべき1つのSTEPを自動で起動する。**

1. `PROGRESS.md` を読む（無ければテンプレートから作成する）
2. 全STEPの一覧（スタンプラリー）を表示して現在地を示す
3. **まだ完了していない最も早い番号のSTEP**を1つだけ特定する
4. そのSTEPに対応するスキルを**そのまま実行して作業を進める**（「この内容で進めてよいですか？」といった開始前の確認は挟まず、上から順に実行する）
5. ただしSTEP1・STEP2は順不同で可（下記「順番のルール」参照）

> 選択式にしないのは、順番が前後してSTEP3以降の依存関係が崩れるのを防ぐため。ユーザーが番号を指定しなくても、常に「次にやるべきSTEP」を自動で進める。
> 開始前の確認も挟まない。lp-start を受けたら、次のSTEPの作業を上から順にそのまま実行する。

### lp-status（進捗確認のみ）が送られたときの動作
- 一覧（スタンプラリー）を表示するだけにとどめ、スキルの起動はしない（確認用）

### STEP完了時の動作（次STEPへは YES/NO で確認）

1. 完了したSTEPを `PROGRESS.md` で `[x]` に更新する
2. 更新後の一覧（スタンプラリー）を表示する
3. **「STEP◯が完了しました。次の STEP△『（内容）』に進んでよろしいですか？（YES / NO）」と確認する**
   - **YES** → 次のSTEPを自動で実行する
   - **NO** → そこで止まり、ユーザーの指示を待つ
4. 全STEP完了なら「🎉 全STEP完了」を表示する（確認は不要）

> STEP開始前の確認はしないが、**STEP完了後に次へ進む区切りでは YES/NO を挟む**。工程の切れ目でユーザーが状態を確認できるようにするため。

---

### 順番のルール（前後させない）

- **STEP1 と STEP2 は順不同で可**：両方が未完了なら、番号の小さいSTEP1から起動してよい（どちらが先でも壊れないため）
- **STEP3 以降は厳密に番号順**：前のSTEPが `[x]` でない限り、そのSTEPは起動しない
- ユーザーが「STEP5をやりたい」のように先のSTEPを指定しても、前提STEPが未完了なら起動せず、「先に STEP◯ を終わらせる必要があります」と案内して、未完了の最も早いSTEPへ誘導する

---

### 表示フォーマット（スタンプラリー＋自動実行）

```
🗺️ LP実装 進行状況

[x] STEP1  初期セットアップ           → project-setup
[x] STEP2  Figma MCP 接続            → figma-mcp-connect
[ ] STEP3  Figma URL を読み込む       → figma-read     ← 👈 次はここ
[ ] STEP4  バリアブルを反映            → figma-read
[ ] STEP5  ドキュメント更新            → figma-read
[ ] STEP6  セクション実装             → lp-implementation
[ ] STEP7  Lighthouse計測            → lighthouse-check
[ ] STEP8  デプロイ確認・GitHubアップロード → deploy-preview
[ ] STEP9  PR作成・レビュー・マージ          → github-review

▶️ STEP3「Figma URL を読み込む」を開始します（figma-read スキル）。
```

> 一覧を表示したら、開始前の確認は挟まず、そのまま次のSTEPの作業に入る。
> 完了後に次へ進むときだけ「STEP◯完了。次のSTEP△に進んでよろしいですか？（YES / NO）」と確認する。
> STEP0（Figma整理）は人の手作業のため、進行管理の対象外（事前準備）とする。

### STEP完了 → 次STEP確認の表示例

```
✅ STEP1「初期セットアップ」が完了しました。

🗺️ LP実装 進行状況
[x] STEP1  初期セットアップ
[ ] STEP2  Figma MCP 接続            ← 👈 次はここ
...

次の STEP2「Figma MCP 接続」に進んでよろしいですか？（YES / NO）
```

### 完了条件（このスキル自体の役割）
- [ ] 起動ワード（lp-start / lp-next）で一覧を表示し、次のSTEPを開始前の確認なしでそのまま実行できる
- [ ] 選択肢を出さず、常にSTEP順（STEP1・2は順不同、3以降は番号順）で進める
- [ ] 前提が未完了の先のSTEPは起動せず、未完了の最も早いSTEPへ誘導する
- [ ] STEP完了ごとに PROGRESS.md を更新し、「次STEPに進むか（YES/NO）」を確認する
- [ ] YESで次STEPを実行、NOでその場で停止できる
- [ ] lp-status では表示のみ行い、起動しない
