## Figma 読み込みスキル（読み込み・要約・トークン反映）

> このスキルは **Figmaデータの読み込みと、DESIGN.md への反映まで**が担当です。
> LPの実装（コードを書くこと）は担当外です（`lp-implementation` が担当）。
> MCP接続がまだなら先に `figma-mcp-connect` スキルを使ってください。

### このスキルを使うタイミング
- MCP接続が済んだあと、セクションのデザインを読み込みたいとき
- バリアブルを DESIGN.md に反映したいとき

### 重要な原則
- **このスキル実行中は絶対に実装（コード生成）をしない**。読み込み・要約・トークン反映のみ。
- **PC・SP の両方**について、`get_design_context`（Figmaの正データ）を取得する。**低解像度スクリーンショットや推測での実装は禁止**。
  - スクショはあくまで見た目確認の補助。テキスト・サイズ・順番・改行・注記などは必ず正データ（`get_design_context`）から取る。
  - 正データが取得できないセクション／画面（SP含む）は、**実装に進ませない**。取得できるまで実装フェーズへ渡さない。
  - blur / glow / 半透明などの装飾を、テキストやラベルと誤読しない（文言は必ず正データのテキストで確認する）。
- 読み込み後は必ず**要約させて人間が目視で承認**してから次へ進む（推測での実装事故を防ぐ）。
- Figmaから取得できなかった値は推測で埋めず「取得できませんでした／暫定」と明記する。

### 手順

**1. セクション単位で読み込ませ、要約させる**
- セクション単位（Hero / Features…）で PC・SP 両方のフレームリンクを渡す
- **必ず `get_design_context`（正データ）から読み込む。スクショだけで判断しない**
- プロンプト例：
  ```
  添付のURLを get_design_context で読み込んでください（PC・SP両方）。まだ実装はしないでください。
  スクリーンショットや推測ではなく、取得した正データをもとに以下を要約してください：
  - レイヤー構成・並び順（PC/SPで順番が変わる場合はその違いも）
  - テキスト（実際の文言。装飾やダミーと混同しない）
  - 使用色 / フォントサイズ / フォントウェイト
  - 画像 / アイコンの数と名前（背景が焼き込まれていないか含む）
  - リンク / ボタンの遷移先（プロトタイプやリンク指定があれば）
  - 細部：下線の位置・gap、要素の重なり順（z-index）、注記の位置
  ```
- 出力された要約を Figma 画面と目視で突き合わせる
- リンク/ボタンの遷移先が Figma に指定されていない場合は「遷移先が未指定」と明示させ、実装前に人間が遷移先を決めて伝える（実装時に `#` やダミーで放置させない）
- 「推測しました」「スクショから判断しました」と返ってきた、または要約が実際と違う場合は、正データを取り直し、取得できるまで実装に進まない

**2. バリアブルを反映する**
- **バリアブルがある場合**：エクスポートした JSON を読み込ませ、DESIGN.md に反映する（この時点で実装はしない）
- **バリアブルが無い／一部の場合**：実際に使われている値を一覧表にまとめさせる
  | 種類 | Figma上の値 | 使用箇所 | 提案する変数名 |
  |---|---|---|---|
  - 人間が表記ゆれ（`#1A73E8` と `#1a73e8` の混在など）を統合・確定する
  - 確定版を DESIGN.md の `:root` に登録する
  - 以降、一覧に無い値は使わない（新しい値は先に一覧へ追加）

**3. 基準ビューポートを設定する**
- Figmaのデザインフレーム幅（SP / PC）を DESIGN.md の「基準ビューポート」に記入する
- `clamp()` の vw 換算はこの値を前提にする

**4. ドキュメントを更新する**
- テンプレートに含まれる README / CLAUDE / DESIGN を、読み込んだ情報で更新する（新規作成ではなく更新）
- Claude Code ベストプラクティス（https://code.claude.com/docs/ja/best-practices）を参照させる

### 完了条件（Definition of Done）
- [ ] **PC・SP の両方**を `get_design_context`（正データ）で取得した（スクショ・推測に頼っていない）
- [ ] 各セクションの要約を人間が承認済み
- [ ] DESIGN.md にカラー・タイポ・スペーシングが反映されている
- [ ] 基準ビューポート（SP / PC）が記入されている
- [ ] 取得できなかった値には暫定である旨のコメントがある
- [ ] この段階でLPの中身は実装していない

### 完了したら次へ
読み込みとトークン反映が終わったら `PROGRESS.md` の STEP3〜5 を `[x]` に更新し、`start-orchestrator` で残タスクを表示する。
その後、`lp-implementation` スキル（セクション実装）へ進む。
