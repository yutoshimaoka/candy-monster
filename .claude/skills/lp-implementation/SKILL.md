## LP 実装スキル（セクション実装）

> このスキルは **Figma読み込み済みの状態から、セクション単位でコードを実装する**のが担当です。
> 前工程（セットアップ・接続・読み込み）と後工程（計測・デプロイ）は別スキルが担当します。

### 前提（このスキルの前に済ませておくこと）
- `project-setup`：初期セットアップ（Vite / Lint など）
- `figma-mcp-connect`：Figma MCP 接続
- `figma-read`：セクションの読み込み・DESIGN.md へのトークン反映

### このスキルを使うタイミング
- Figmaの読み込みとトークン反映が済み、実際にコードを書き始めるとき
- セクションを追加・修正するとき

### 手順（セクション単位で繰り返す）
1. 実装ガイドライン（`CLAUDE.md` / `DESIGN.md` / `.claude/rules/` 配下）に沿って、対象セクションを実装する
2. 実装画面のスクリーンショットを撮る
3. Figmaのフレームと並べて比較する（ズレ・余白・フォントサイズ）
4. **見た目だけでなく computed style（実際に適用された値）を Playwright 等で実測**し、Figmaの正データと突き合わせる（HMRキャッシュや低解像度スクショによる誤検証を排除するため）
5. 差分があれば修正する
6. 下記「完了条件」を満たすか確認する
7. セクション単位でコミットする
8. 次のセクションへ進む

- プロンプト例：「実装ガイドラインを踏まえて【セクション名】を実装してください。実装後、スクリーンショットと computed style の実測でFigmaの正データと比較し、差分を報告してください。」

> ⚠️ 検証前に**ハードリロード／キャッシュクリア**する。Vite dev の `@import` は HMR で更新されないため、CSSは `<link>` 分割かビルド後に検証する（旧CSSでの誤検証を防ぐ）。

### レスポンシブの実装方針
- 値の伸縮（フォント・余白・最大幅）は `clamp()`
- カードの段組みは Grid auto-fit（`repeat(auto-fit, minmax(min(240px,100%), 1fr))`）
- タグ・ボタンの折り返しは `flex-wrap: wrap`
- PC / SP で並び順が変わる箇所は `grid-template-areas` で切替（`display:contents` + `order` は不安定なため使わない）
- 構造が根本的に変わる箇所のみメディアクエリを併用

### セクション完了条件（Definition of Done）
- [ ] Figmaとのスクショ比較でズレがない
- [ ] computed style の実測値がFigmaの正データと一致している
- [ ] 細部が一致している：下線の位置・gap、要素の重なり順（z-index）、注記の位置、文言（装飾と混同していない）
- [ ] PC / SP両方で崩れがない（並び順の切替も正しい）
- [ ] リンク・ボタンの遷移先が設定されている（`#`・ダミー放置なし）
- [ ] 実装ガイドラインを満たしている
- [ ] Lintエラーがゼロ
- [ ] コンソールエラーがない
- [ ] セクション単位でコミット済み

### 完了したら次へ
全セクションの実装が終わったら `PROGRESS.md` の STEP6 を `[x]` に更新し、`start-orchestrator` で残タスクを表示する。
その後、`lighthouse-check`（品質計測）→ `deploy-preview`（デプロイ）へ進む。
