## レビュー対応スキル（指摘反映 → 再レビュー）

> このスキルは **レビュワーの指摘を反映し、PR を再レビューに回すまで**を担当します。
> 「レビューは直す作業ではなく、合意を作る作業」。黙って直さず、1件ずつ対応内容を返します。
> PR作成・マージの全体フローは `github-review` スキル（STEP9）を参照。

### このスキルを使うタイミング
- 出した PR にレビューコメントが付き、それを反映するとき
- 修正後に再レビューを依頼するとき

### 前提
- 対象の PR が既に存在する（`github-review` の 9-1/9-2 で作成済み）
- `gh`（GitHub CLI）がインストール・認証済み

### 手順

**1. 指摘を全件洗い出す**
```bash
gh pr view <PR番号> --comments
```
- サマリコメントと行単位コメントの両方を拾う（折りたたまれて見落としやすい）
- `ファイル / 行 / 指摘 / 対応方針` の対応表を作る

**2. 仕分けする（スコープを広げない）**
| 分類 | 例 | 動き方 |
|------|----|--------|
| すぐ直す | 誤字・直値・alt漏れ・命名・規約違反 | その場で修正 |
| 相談する | 設計方針・仕様解釈・影響大 | 直さず、意図を確認・提案 |
| 別PRにする | 今回と無関係な改善・大きなリファクタ | このPRでは触らず宣言する |

**3. 1件ずつ直して、意味のある単位でコミットする**
```bash
git add <対象>
git commit -m "fix: <対応内容>（レビュー指摘 #<番号>）"
```
- 指摘ごと・意図ごとにコミットを分ける（1コミットに混ぜない）

**4. まとめて push する**
```bash
git push
```
- force push は避ける（レビュー中の差分が消える）。必要な時のみ事前に一言

**5. 各スレッドに1件ずつ返信する**
- 直した：「対応しました。◯◯を△△に修正（コミット: abc1234）」
- 相談：「意図は□□でした。A案/B案どちらが良いですか？」
- 別PR：「別PR（#12）で対応します。本PRのスコープ外のため」
- Resolve は基本レビュワーに委ねる（チームの運用に従う）

**6. 再レビューを依頼し、Slack共有用のサマリを出力する**
- まとめて1回だけ依頼する（1件ごとに毎回依頼しない）
```bash
gh pr edit <PR番号> --add-reviewer <レビュワー名>   # Re-request review
gh pr view <PR番号> --json url,title --jq '.url, .title'   # URL確認
```
- 依頼後、**Slackにそのまま貼れる共有用テキストをコピーブロックで出力する**（下記フォーマット）。
  - PRのURLを含める
  - 対応した内容の概要を、項目ごとに **各1〜2行** で簡潔にまとめる
  - コピーしやすいよう、コードブロック（```）で囲んで1つにまとめて出力する

#### Slack共有用フォーマット（この形で出力する）
````
```
🔵 再レビューのお願い：<PRタイトル>
PR: <PRのURL>

対応内容：
・<指摘1への対応を1〜2行で>
・<指摘2への対応を1〜2行で>
・<指摘3への対応を1〜2行で>

相談中：<あれば1行。なければ省略>
別PR対応：<あれば1行。なければ省略>
```
````
- 実際の出力例：
````
```
🔵 再レビューのお願い：Hero：見出し余白を修正
PR: https://github.com/minimo-inc/project-a-lp/pull/12

対応内容：
・ボタンのalt漏れを修正（装飾画像はalt=""に）
・見出しの余白を直値からDESIGN.mdの変数に置換
・SPの改行位置をFigma通り3行に修正

相談中：カード段組みのbreakpointは現行維持で良いか確認したいです
```
````

### 完了条件（Definition of Done）
- [ ] レビュー指摘を全件洗い出し、仕分けした
- [ ] すぐ直す指摘を、指摘ごとにコミットを分けて修正・push した
- [ ] 各スレッドに1件ずつ返信した（黙って直していない）
- [ ] 相談・別PRの項目は、直さず方針を返信した
- [ ] 再レビューをまとめて1回依頼した
- [ ] Slack共有用の「PR URL＋対応概要（各1〜2行）」をコピー可能な形で出力した

### やらないこと（アンチパターン）
- 黙って直して push だけする／全部directに取り込む（スコープ肥大）／1件ごとに再レビュー依頼／force pushで履歴書き換え／意図を確認せず脊髄反射で直す

### 完了したら
承認が揃ったら `github-review` スキルのマージ手順（`gh pr merge`）へ。
